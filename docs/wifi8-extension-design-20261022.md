# WiFi 知識專區：延伸知識、圖表與概念圖譜（設計與分階段計畫）

日期：2026-10-22　狀態：Phase 1 實作中（旗標關閉、隔離環境），其餘為計畫。

## 決策（使用者，2026-10-22）
1. **允許引用模型的一般知識**，但必須明確標示，不得取代或混入文件依據。
2. **圖表：數據圖與概念圖都要。**
3. **投入概念圖譜（層級 C）；LLM 抽取的關係直接寫入，不套用 v2.6「AI 推論未審核不得當正式」的規則。** 這是對本專區的明確例外；仍保存來源段落、抽取模型與時間，方便除錯與事後修正，並在畫面上標示「圖譜關聯（LLM 抽取）」。
4. 順序：WiFi 專區先做層級 A、B，再做圖表與概念圖譜；圖表基礎先在 CSIT「報告查詢助手」試辦。

## 回答的三層結構（所有階段共用）
| 層 | 內容 | 驗證 |
|---|---|---|
| 文件依據 | 句末 `[S#]` 引用，沿用現有依據檢核 | 程式逐句檢核引用與數值 |
| 圖譜關聯 | 相關主題／概念／版本沿革，`[G#]` 指向圖譜節點與其來源 | 只驗證節點存在與來源段落；內容為 LLM 抽取 |
| 一般知識補充 | 模型的一般知識，固定標示「未經專區文件驗證」 | 不檢核；不得含專區文件的數值、版本、日期，不得引用 `[S#]` |
另附「你可能還想問」（最多 3 題）。依據檢核只作用在第一層，畫面上三層用不同標示。

## Phase 1（A＋B）：兩層回答、相關主題與版本沿革
- 旗標 `KM_WIFI8_AGENT_EXTENSION`（預設關閉，關閉時行為與現行完全相同，原有品質監控不受影響）。
- `src/wifi8/extension.py`：延伸提示詞、答案切分（主體／相關／一般知識／後續問題）。
- `src/wifi8/graph.py`：唯讀、固定 Cypher 範本（相關主題、文件的相關文件、版本沿革）；逾時、深度與筆數上限；Neo4j 不可用時降級為無圖譜，不影響回答。
- 前端：延伸知識區塊與後續問題按鈕。
- 驗證：單元測試；用隔離環境對真實資料（唯讀）跑固定題集，人工檢視延伸品質，確認主體的依據檢核結果不退步。

## Phase 2：圖表
- LLM 不產生 HTML／SVG，只輸出受限的圖表規格（JSON）：類型、軸、資料點、每個資料點的來源引用。
- 後端驗證：資料點數值必須出現在被引用的來源（沿用數值檢核）；不合格的點不畫並說明。
- 前端：固定函式庫繪製（數據圖）與 Mermaid（概念圖，依賴 Phase 3），所有文字先轉義，補內容安全政策。
- 先在 CSIT 報告查詢助手試辦（數值已結構化在 `km_test`，驗證容易）；WiFi 專區的數據圖只在文件有明確數值表時才提供。

## Phase 3：概念圖譜
- 節點 `Wifi8Concept`（concept_id、名稱、別名、類型）；關係 `RELATED_TO`／`INTRODUCED_IN`／`DEPENDS_ON`／`DEFINED_IN`，帶來源段落、抽取模型、抽取時間、`source=llm`。
- 抽取：依文件分窗、循序呼叫 LLM（不併發，避免閘道逾時），結構化輸出；別名正規化重用查詢擴展表並擴充；可重跑、冪等（MERGE）。
- 查詢：固定範本，深度預設 2、最大 3；不讓 LLM 寫 Cypher。
- 重建：圖是衍生資料，可由文件重建；寫入前保留舊圖，驗證後切換。

## 風險
- 一般知識可能出錯：標示加免責，並在評測中加入「延伸是否誤導」人工評分。
- 延遲與成本：多一輪圖譜查詢與較長輸出；時間預算沿用 90 秒上限。
- WFA 專有文件：延伸內容不得變相逐字轉述。
- LLM 抽取關係可能有誤（已決定接受）：畫面標示來源與「LLM 抽取」，提供回報錯誤關係的方式（後續）。
- 部署：所有變更需兩區一致，並經你授權才部署。
