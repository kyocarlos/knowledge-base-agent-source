# KM Phase 1 2026-W38 週報

## 本週範圍

本週補登 W37 未完成的 KM 搜尋精確度與 Rerank 工作，並記錄 W38 的 ingest worker 與 CSIT STAGE read-only 整合進度。CSIT Web、資料庫 schema、workflow、write API 與 NAS 直連不納入本週完成範圍。

## 已驗證

- KM 搜尋已可呈現 retrieval/rerank/document quality score、grade、score breakdown、model identity 與 fallback 狀態。
- Qwen3-Reranker-0.6B 在真實 KM search runtime active；模型異常時回退 baseline。
- Qdrant lifecycle hard filter 與受控 reindex 完成：4,001 points、lifecycle mismatch 0；Draft/non-current 不進 rerank。
- `kb-celery-ingest` 更新至 `km-v26-rerank:0d88baab`，Celery ready/ping、Embedding、Qdrant、Neo4j、Ollama 初始化成功；既有 6 筆舊 queued task records 已清理。
- CSIT STAGE 使用同一 Cookie session 完成 `modules → records → cases → tasks → files` 動態 GUID 查詢，檔案下載 HTTP 200。
- KM CSIT read-only client、GET-only proxy routes 與獨立 `csit:read` RBAC 已完成 local compile/auth validation，預設仍為 disabled。

## 尚未宣稱

- Golden query 尚未補齊正確 document/chunk/relevance qrels，因此不能宣稱 Recall、Precision、MRR、nDCG 或命中率已有固定比例提升。
- Upload → ingest → search 的新文件端到端驗證尚未完成。
- CSIT proxy 尚未 Production activation；DNS、CA trust、受控 reader credential 與前端瀏覽頁仍待處理。
- 不執行 CSIT POST/PUT/DELETE，不連 CSIT PostgreSQL/NAS，不將 CSIT 資料直接發布為 KM published/current。

## W39 建議最小步驟

1. 完成 qrels 與離線 evaluator artifact。
2. 以安全測試文件完成 upload → ingest → search E2E。
3. 完成 CSIT CA/DNS/KM reader credential preflight。
4. 建立只讀 CSIT 瀏覽頁並執行 read-only acceptance。
5. Review 通過後再評估 CSIT report/file → KM ingest。
