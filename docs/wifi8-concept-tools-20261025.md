# WiFi 助手：概念圖譜關係型問題工具（2026-10-25）

## 目的
回答「X 有哪些測項」「X 依賴／使用什麼」「X 屬於哪個功能」「A 和 B 有什麼關係」這類關係型問題。第五輪檢索對照實驗顯示概念圖譜不適合做檢索過濾或重排，因此只當結構化補充，不改變現有檢索。

## 工具（唯讀、固定 Cypher、有列數與時間上限）
- `concept_relations(name, relation_type?, direction?)`：某概念的關係，依關係類型與方向分組，每筆附原文證據句。
- `concept_compare(a, b)`：兩概念的直接關係、共同提到的文件、共同關聯的其他概念。

## 行為
- 名稱解析在程式內完成（名稱／別名、忽略大小寫與標點、單複數；較長名稱包含查詢字串時為次選，文件多者優先），不讓模型寫查詢。
- 證據句登記成一般 `[S#]` 引用（`location_label` = 「概念圖譜證據句」），主體回答的接地檢查可驗證；前端引用面板會顯示該標示。證據句所屬文件不在文件庫時，該句不引用。
- 指定的方向沒有結果時自動回傳另一個方向並註明（模型常選反方向）。
- 找不到概念、尚未載入、Neo4j 不可用時回傳錯誤，其他工具與回答不受影響。
- 系統提示（旗標開啟才附加）要求：只引用有 `[S#]` 的證據句、註明來自概念圖譜（LLM 自動抽取、僅涵蓋部分文件）、與文件檢索不一致時以文件為準、方向照 `direction` 表達。

## 設定
- `KM_WIFI8_CONCEPTS`（預設 0）：1 時提供兩個工具並附加提示；任務在旗標開啟時也會建立 Neo4j 連線（原本只在延伸知識開啟時）。與 `KM_WIFI8_AGENT_EXTENSION` 互相獨立。
- 關係類型與圖譜寫入端一致（測試比對集合）。

## 驗證（候選程式，未部署）
- WiFi 測試 270 項通過（含新增 9 項：名稱解析、證據登記與重複編號、未知文件略過、錯誤處理、比較、旗標關閉與無圖譜、旗標開啟的完整流程、方向回退）。
- 在 DA40 搜尋 worker 以候選模組覆蓋（不改映像）、真實 Neo4j 圖譜與真實 LLM，循序跑 12 題：工具都被正確選用；不存在的概念（Quantum Router）正確拒答並說明圖譜未找到；回答皆註明圖譜來源與限制；接地檢查無 source mismatch。
- 已知限制：圖譜只涵蓋約 152／503 份文件；`concept_compare` 的共同文件清單沒有逐篇證據句，回答中該清單只能標為工具資料；Test Plan 的 TESTED_BY 仍有少量證據缺測試名稱的關係。

## 部署（待授權）
需重建兩區 search worker 疊層映像（agent.py、graph.py、新增 concept_tools.py、tasks.py），並在兩區 override 加 `KM_WIFI8_CONCEPTS`；兩區都要驗收。回復：旗標設 0 並重建，或換回前一映像。
